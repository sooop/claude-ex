# 확장 위임 프로토콜 설계 (2/2) 브라우저 확장 측

Oct 16, 2026 · @sooop

## 1. 요약

결론: 확장은 "라우터 + 권한 게이트 + op 레지스트리" 세 가지만 구현한다. 사이트별 로직은 어댑터로, 권한이 필요한 동작은 op로 등록한다. 메시지 형식과 수명주기, 오류 코드는 1/2 문서 3장을 그대로 따른다.

확장이 맡는 일은 다섯 가지다.

- 페이지에서 온 메시지를 검증해 서비스 워커로 중계한다.
- op를 스키마, 권한, 동의 순으로 검사한 뒤 실행한다.
- 아티팩트가 제공하는 op(예: AI 판정)를 호출하는 클라이언트 역할을 한다.
- 사용자 동의와 허용 목록을 확장 UI에서 관리한다.
- 호출을 감사 로그로 남긴다.

하지 않는 일은 임의 URL fetch, 임의 스크립트 실행, 쿠키·토큰 반환, 사용자 동의 없는 쓰기 동작이다.

## 2. 구성요소

확장은 Manifest V3 확장 하나로, 다섯 개 구성요소를 둔다. 권한이 필요한 코드는 서비스 워커에만 둔다.

| 구성요소 | 책임 |
| --- | --- |
| manifest | `content_scripts`는 아티팩트 호스팅 오리진(구성값)에만 매칭하고 `all_frames`를 켠다(아티팩트가 iframe이기 때문). `permissions`는 최소 집합(storage, downloads, scripting)만 두고, 사이트 접근은 `optional_host_permissions`로 런타임에 요청한다 |
| 콘텐츠 스크립트 | 격리 월드에서 실행. window 메시지를 필터링해 서비스 워커 포트로 넘기고, 응답을 다시 window로 돌려준다. 비즈니스 로직 없음 |
| 서비스 워커 | 라우터, op 레지스트리, 핸들러, 권한 게이트, 감사 로그. 상태를 메모리에만 두지 않는다 |
| 팝업 | 연결 상태, 최근 호출 20건, 현재 오리진 허용 토글, 동의 확인 창 |
| 옵션 페이지 | op·오리진별 허용, 호스트 권한 부여(사용자 제스처 필요), 감사 로그 열람·삭제 |
| 오프스크린 문서(선택) | 서비스 워커에는 DOM이 없으므로, HTML을 DOMParser로 파싱해야 하는 어댑터가 쓴다 |

아티팩트 오리진이 바뀔 수 있으므로 매칭 오리진은 코드에 박지 않고 설정으로 둔다. 새 오리진을 쓰려면 옵션 페이지에서 사용자가 허용해야 한다.

## 3. 메시지 라우팅과 서비스 워커 수명

호출 하나는 아티팩트, 콘텐츠 스크립트, 서비스 워커를 거쳐 외부 자원에 닿고, 같은 경로로 돌아와 result 한 번으로 끝난다.

서비스 워커는 유휴 시 종료될 수 있어 아래 규칙으로 대응한다.

- 호출 상태를 메모리에만 두지 않는다. 진행 중인 호출의 id, op, 오리진, 시작 시각만 `chrome.storage.session`에 기록한다.
- 포트가 끊기면(워커 재시작 포함) 콘텐츠 스크립트가 진행 중인 id마다 `internal`(`detail: worker_restarted`, `retryable: true`) result를 페이지로 보내고 포트를 다시 연다.
- 페이지가 이동하거나 새로고침되면 콘텐츠 스크립트가 그 페이지의 모든 호출에 cancel을 전달해 워커의 작업을 중단한다.
- 장시간 작업은 progress를 주기적으로 보내되, 워커가 계속 살아 있다는 가정에 기대지 않는다. 끝내지 못하면 위의 재시작 경로로 오류를 돌려준다.
- 포트로는 JSON만 오가므로 ArrayBuffer는 base64 청크(청크당 512KiB)로 나눠 보내고 워커에서 조립한다.
- 호출한 탭은 `sender.tab`에서 얻어 op 컨텍스트에 넣는다(동의 창과 `page.fill`이 쓴다).

## 4. Op 레지스트리와 호출자 역할

### 4.1 Op 정의

모든 op는 아래 필드를 가진 정의 객체 하나로 등록한다. 핸들러는 정의를 통과한 호출만 받는다.

| 필드 | 내용 |
| --- | --- |
| name, ver | `domain.verb` 이름과 정수 버전 |
| kind | `read`, `write`, `sensitive` |
| argsSchema | 필드, 타입, 길이 제한을 선언. 선언하지 않은 필드는 거부 |
| resultSchema | 반환 전 정제 규칙(태그 제거, 길이·개수 제한) |
| permissions | 필요한 chrome 권한과 호스트 권한 |
| consent | `none`, `first_use`, `every_time` |
| limits | timeoutMs 상한, maxConcurrent, 최대 페이로드, 오리진당 분당 호출 상한 |
| handler | `async ({args, signal, progress, sender, log}) => data` |

실행 순서는 항상 봉투, 오리진 허용, op 존재, argsSchema, 권한, 동의, 동시성·레이트 리밋, 핸들러 실행, resultSchema 정제, result 전송이다. 어느 단계에서든 실패하면 그 시점에 오류 result로 끝난다.

### 4.2 핸들러와 어댑터 규칙

- 핸들러의 모든 네트워크 요청은 어댑터가 선언한 호스트 허용 목록 안에서만 나간다. 리다이렉트도 목록 안에서만 따라간다.
- 응답 크기 상한을 두고, `signal`이 abort되면 진행 중인 fetch를 즉시 중단한다.
- 어댑터는 `{id, hosts[], buildRequest(params), parse(body) → items}` 형태로 두고, 번들 안에만 둔다. 원격에서 규칙이나 코드를 내려받아 실행하지 않는다.
- 사이트가 차단하거나 확인 절차를 요구하면 우회하지 않고 `blocked`로 돌려준다. 화면 구조를 읽지 못하면 `parse_failed`다.
- 사용자 로그인 쿠키가 필요한 어댑터는 요청에만 쿠키를 쓰고, 쿠키·헤더를 result에 담지 않는다.

### 4.3 호출자 역할 (확장 → 아티팩트)

확장이 아티팩트의 op를 부르는 경우의 규칙이다.

- 아티팩트의 hello\_ack에 있는 `provides`를 확인하기 전에는 call을 보내지 않는다. 연결 대기 중이면 hello를 최대 3회 재시도한 뒤 실패로 처리한다.
- id는 확장이 만들고, 대기 시간은 `timeoutMs + 2000ms`다. `busy`는 지수 백오프로 최대 2회 재시도한다.
- 아티팩트가 돌려준 결과도 신뢰하지 않는다. 스키마(예: 확률 합, ref 일치)를 검증하고 화면에는 textContent로만 내보낸다.
- 페이지를 새로고침하면 아티팩트의 능력 캡시를 버리고, 새 hello로 다시 채운다.

## 5. 권한과 동의 모델, 보안

권한은 네 겹으로 나눠 부여한다. 위험한 op일수록 맨 아래 겹이 매번 사용자 확인을 요구한다.

| 겹 | 부여 방식 | 범위 |
| --- | --- | --- |
| 설치 권한 | manifest `permissions` | storage, downloads, scripting 등 최소 집합 |
| 호스트 권한 | `optional_host_permissions`. 옵션 페이지에서 사용자 제스처로 요청 | 어댑터가 쓰는 도메인만 |
| 오리진 허용 | 옵션 페이지 허용 목록 | 어느 아티팩트 오리진(ns)가 어떤 op를 쓰는지 |
| 호출 동의 | op의 `consent` 수준 | `first_use`는 처음 한 번 확인 후 기억, `every_time`은 호출마다 확인 |

동의 화면은 페이지 안이 아니라 확장 UI(팝업 또는 별도 확인 창)로 띄운다. 페이지가 화면을 흉내 낼 수 없게 하기 위함이다. 동의가 없으면 호출을 붙잡아 두지 않고 즉시 `not_granted`와 `detail.hint`(확장에서 허용 필요)를 돌려준다. 아티팩트가 사용자에게 안내한 뒤 재시도한다.

### 보안 체크리스트

- 콘텐츠 스크립트 주입은 허용된 오리진에만 한다. 페이지에서 온 메시지는 전부 신뢰하지 않는 입력으로 다룬다.
- 서비스 워커는 `onConnect`의 `sender.url`과 탭 정보가 허용 목록과 일치하는지 다시 확인한다.
- 레지스트리에 없는 op는 거부한다. 인자에 URL이 있으면 호스트 허용 목록과 대조하고, 사설 IP·`file:`·`chrome-extension:` 스킴은 막는다(SSRF 방어).
- 쿠키, 토큰, 요청 헤더, 확장 내부 경로는 어떤 result에도 담지 않는다.
- 외부 사이트에서 읽은 텍스트는 태그를 제거하고 길이·개수를 제한한다. result의 `meta.untrusted: true`로 표시해, 아티팩트가 AI 프롬프트에 넣을 때 데이터로 구획하게 한다.
- 오리진·op별 분당 호출 상한을 두고 초과하면 `busy`를 돌려준다.
- 감사 로그는 시각, 오리진, op, 결과 코드, 크기만 최근 500건 남기고 본문은 저장하지 않는다. 옵션 페이지에서 열람·삭제할 수 있다.
- 원격 코드 로드와 `eval`을 쓰지 않는다. 모든 어댑터는 번들 안에 둔다.
- postMessage 채널은 인증되지 않는다. 같은 window의 다른 스크립트가 아티팩트를 위장할 수 있으므로, `write`·`sensitive` op는 안내문이 아니라 확장 UI의 동의로만 통과시킨다.

## 6. 오류 처리, 관측, 테스트, 호환성

### 6.1 오류 매핑

| 확장 내부 상황 | error.code | 재시도 |
| --- | --- | --- |
| 스키마·크기 위반 | invalid\_request, payload\_too\_large | 아니오 |
| 등록 안 된 op 또는 버전 | unsupported\_op | 아니오 |
| 허용·동의 없음 | not\_granted | 아니오 |
| 동시성·분당 한도 초과 | busy | 예 |
| fetch 실패, DNS 오류 | network | 예 |
| 403, 캡차, 확인 절차 | blocked | 아니오 |
| 응답 파싱 실패 | parse\_failed | 아니오 |
| 제한 시간 초과 | timeout | 예 |
| 서비스 워커 재시작 | internal (`detail: worker_restarted`) | 예 |

### 6.2 관측

툴바 배지는 연결 상태와 진행 중 호출 수를 보여준다. 팝업에는 최근 20건, 옵션 페이지에는 감사 로그 500건이 있다. 어댑터는 성공률과 파싱 실패 비율을 로컬에만 집계해, 사이트 구조가 바뀌었을 때 빨리 알아챈다.

### 6.3 테스트

1. 어댑터 단위: 저장해 둔 응답 샘플(HTML, JSON)로 parse 결과를 비교한다. 실제 사이트에 주기적으로 한 건씩 물어보는 카나리 점검을 둔다.
2. op 단위: 스키마 위반, 크기 초과, 동시성, 동의 없음.
3. 통합: 정적 HTML 모의 아티팩트 페이지로 hello, call, progress, cancel, 타임아웃, 중복 result를 재현한다.
4. MV3 수명: 호출 중 서비스 워커를 강제 종료해 `worker_restarted` result가 나가는지 확인한다.

### 6.4 호환성과 배포

확장은 hello에 `supportedVersions`(예: \[1, 2\])를 담고, 양쪽이 공통으로 지원하는 가장 높은 버전을 쓴다. op도 같은 방식으로 `ver` 교집합을 본다. 스토어 심사에 시간이 걸리므로, 새 기능은 아티팩트의 기능 토글로 점진 공개하고 확장은 두 릴리스 동안 하위 호환을 유지한다.

## 7. 활용 예 5가지의 확장 측 구현 포인트

예시의 정의(인자, 결과)는 1/2 문서 6장에 있다. 여기서는 확장이 신경 써야 할 구현만 정리한다.

| op | 필요 권한 | consent | 핵심 구현 | 주의 |
| --- | --- | --- | --- | --- |
| `web.query` | 어댑터 도메인의 호스트 권한 | none | 서비스 워커에서 fetch. 어댑터의 build·parse. 타임아웃 내 재시도 1회 | 쿠키 비반환. 차단 감지 시 `blocked`, 우회 금지 |
| `ai.decide` (확장이 호출) | 없음 | none (앱의 허용 토글이 게이트) | 후보를 모아 아티팩트에 call하고, 결과를 검증해 팝업이나 패널에 표시 | 앱이 busy면 백오프. 후보 텍스트는 길이·태그 정제 후 전송 |
| `file.save` | downloads | `first_use`(폴더 변경 시 `every_time`) | base64 청크(각 512KiB)를 조립 후 `chrome.downloads.download`, `conflictAction: uniquify` | `..`·절대 경로 거부, 확장자 허용 목록, 총 용량 상한. 포트로는 JSON만 오므로 바이너리는 찭크로 나눠 보낸다 |
| `page.fill` | scripting, 대상 호스트 권한 | `every_time` | `chrome.scripting.executeScript`로 어댑터가 고정한 셀렉터에 값을 넣고 input·change 이벤트를 발생 | 대상 탭을 사용자가 고르게 할 것. 제출·저장 버튼 조작 금지. 채우지 못한 필드는 `skipped`로 보고 |
| `kv.put`, `kv.get` | storage(필요 시 unlimitedStorage) | `first_use` | 키에 `ns:` 접두어를 붙여 오리진 간 격리. `rev` 비교(낙관적 잠금)로 쓰기 | rev가 다르면 덮어쓰지 않고 `conflict`. 값 크기 상한을 둔다 |

## 8. 플러그인 확장 (2026-10-18, `docs/plans/2026-10-18-plugin-hub.md`)

MV3는 원격 코드를 실행할 수 없으므로, 새 op나 어댑터를 허브 번들 밖에서 더하려면 **그 코드를 담은 별도 확장(플러그인)**이 허브에 등록한다. 아티팩트는 허브 하나와만 v2로 통신하고, 허브가 플러그인에 중계한다. 플러그인 코드도 여전히 어떤 확장 번들 안에 있으므로 4.2와 5장의 "원격 코드 금지"를 어기지 않는다.

### 8.1 플러그인 채널

허브와 플러그인 사이에만 쓰는 계약이다. 타입과 검증은 `src/sdk/plugin.ts`, 플러그인 쪽 구현은 `src/sdk/companion.ts`(`serveAsCompanion`).

| 방향 | 수단 | 내용 |
| --- | --- | --- |
| 등록 (플러그인 → 허브) | `runtime.sendMessage(HUB_ID)` | `{kind:'abp-plugin/register', sdk, name, version, catalog}` → `{status:'active'|'pending'|'rejected', reason?}`. 플러그인 서비스 워커가 시작될 때마다 보낸다. 허브가 없으면 실패를 무시한다 |
| 호출 (허브 → 플러그인) | 호출 1건마다 `runtime.connect(extId, {name:'abp-plugin/call'})` | `invoke{op, ver, adapter?, args, timeoutMs, sender{ns, origin}}` → `progress`* → `result`. 허브의 `cancel` 또는 포트 끊김이 취소다 |

- 카탈로그는 함수 없는 선언이다: `{ops: PluginOpDef[], adapters: {[허브 op]: AdapterDef[]}}`. 어댑터 형식은 1/2 문서 3.8의 `meta.describe` 어댑터 상세와 같다. 크기 상한 32KiB.
- 플러그인은 `sender.id === HUB_ID`인 연결만 받고, 받은 인자를 자기 스키마로 다시 검증한다.
- 연결에 실패하면(플러그인 삭제·비활성) 허브는 `internal`, `detail: plugin_unreachable`, `retryable: true`로 답한다.

### 8.2 등록과 승인

- 처음 등록하면 승인 대기다. 허브는 툴바 배지(대기 건수, 번역 작업 배지가 우선)로 알리고, 사용자가 팝업의 승인 카드에서 허용하거나 거부한다.
- 승인한 플러그인의 선언(kind, 설명, 스키마)은 그대로 믿는다.
- **카탈로그 해시가 승인 때와 다르면 그 플러그인을 끄고 다시 승인 대기로 돌린다.** 코드만 바뀌고 카탈로그가 같으면 다시 묻지 않는다. 같은 해시로 거부한 등록은 다시 묻지 않는다.
- 허브 내장 op와 겹치는 op, 다른 플러그인이 이미 쓰는 op 이름·어댑터 id는 거부한다. 어댑터는 허브가 정한 어댑터 op(현재 `web.query@1`)에만 보탤 수 있다.
- 상태는 `chrome.storage.local`의 `plugins`에 둔다. 서비스 워커가 재시작되면 이 상태를 읽어 레지스트리를 만든 뒤에 세션의 hello를 보낸다.

### 8.3 `web.query`의 어댑터 병합

- `web.query@1`은 허브 내장 op다. 인자는 `{adapter, params}`이고, 허브가 어댑터를 가진 플러그인을 찾아 `params`를 그 어댑터 스키마로 검증한 뒤 넘긴다. 결과 meta에는 `untrusted: true`를 붙인다.
- 활성 어댑터가 없으면 `provides`에서 빠진다. 승인·해제·재승인 대기로 카탈로그가 바뀌면 열린 세션에 `catalog_changed`를 보낸다.

### 8.4 공존

같은 프레임에 두 확장이 v2로 응답하지 않도록, 플러그인은 아티팩트와 v2로 직접 통신하지 않는다(1/2 문서 3.8의 "확장은 한 번에 하나" 전제를 유지). postal은 v1만 직접 처리하고 v2는 허브를 거친다.
